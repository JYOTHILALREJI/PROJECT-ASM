# PRODUCT REQUIREMENTS DOCUMENT

# Documents & NOC Automation Module

**Product:** Existing Workforce / Operations Web Application
**Module:** Documents
**Feature:** NOC Automation + Employee Document Management
**Version:** 1.0
**Status:** Product Specification
**Platform:** Existing Web Application
**Primary Users:** HR, PRO, Operations, Admin, Management

---

# 1. Executive Summary

The existing application will be extended with a new **Documents** section in the main side-panel navigation.

The Documents module will become the central repository for:

1. **NOCs**
2. **Employee Documents**
3. Future document categories

The first major workflow will be **automated NOC creation**.

Instead of manually preparing an NOC in Word/PDF and copying employee information, the user will:

> Create NOC Request → Enter Client/Project Details → Select/Identify Employees → System Retrieves Employee Records → Review Employee Table → Edit/Add/Remove Employees → Confirm → Generate NOC → Preview → Download / Print → Automatically Store

The employee information should originate from the application's existing employee database wherever possible, reducing manual entry and preventing passport/name/company inconsistencies.

The generated NOC must reproduce the provided reference format as closely as technically possible, including:

* Header
* Arabic header text
* Company branding/logo
* Contact information
* Recipient block
* Date
* Subject
* Project
* NOC body
* Employee table
* Signature/contact section
* Footer
* A4 page dimensions
* Multi-page behavior

The reference documents consistently use the employee fields **Name, Trade, Company, Nationality and Passport #** in the NOC table. 

---

# 2. Product Vision

## Vision

Create a centralized **document operating system for workforce administration**, starting with automated NOC generation and employee document management.

The module should eliminate repetitive administrative work and provide a single source of truth for:

* Employee identity information
* Passport information
* Employee documents
* NOCs
* Client-specific documentation
* Historical document records

---

# 3. Business Objectives

### Primary objectives

* Reduce manual NOC preparation time.
* Eliminate repetitive employee data entry.
* Reduce passport/name/employee-data errors.
* Standardize NOC formatting.
* Make NOCs immediately printable.
* Maintain a searchable historical archive.
* Centralize employee documents.
* Make documents accessible from the employee record.
* Enable easy retrieval of historical NOCs by client, month and year.
* Provide auditability for document creation and modification.

### Target outcome

A user should be able to prepare a complete NOC for 20–50 employees in a few minutes rather than manually constructing the document.

### Important behavior

When a database employee is selected, the system initially populates the values from the employee record.

However, the NOC preparation table becomes a **document snapshot**.

Therefore:

> Editing the NOC should NOT automatically modify the master employee record.

Instead:

```text
Employee Database
       ↓
NOC Snapshot
       ↓
User edits NOC
       ↓
Generated NOC
```

This is important for historical accuracy.

# 20. NOC Body

The NOC body must be template-driven.

The reference samples use wording substantially along the following lines:

> The organization confirms that the listed workers may work with the recipient company and accepts responsibility for their salary, welfare and other requirements, including liabilities and claims arising from injury or untoward incidents at site. 

However, the supplied samples contain slightly different wording, such as "We would like..." and "We want...".  

Therefore, the system should implement a **controlled template**, rather than automatically rewriting the legal wording.

### Admin capability

Admin can configure:

```text
NOC Template Name
Body Text
Company Name
Arabic Header
Logo
Footer
Signatory Name
Designation
Phone
Email
Website
```

Normal users should not be able to casually change the approved legal wording.

Generated NOCs must be true **A4 documents**.

### Requirements

* Correct footer position

* Consistent font sizing
* Consistent line spacing

# 22. Multi-Page NOC Behavior

This is important because the reference NOCs contain different employee counts and some span two pages.

For example, the supplied Arabian Ranches NOC contains 20 employees. 

The Warsan example contains 26 employees across two pages. 

The system should therefore dynamically paginate.

### Rules

If the employee table reaches the bottom of page 1:

```text
Page 1
Header
NOC information
Body
Employee table
↓
Page break
↓
Page 2
Header
Employee table continued
Footer/signature
```

The table header should repeat:

```text
Sl.No | Name | Trade | Company | Nationality | Passport
```

Rows should never be cut horizontally.

Preferably, a single employee row should not be split across two pages.

# 60. PDF Rendering Architecture

```text

   ↓

   ↓
```

# 72. Key Product Principle

The most important architectural principle for this module is:

> **The employee database is the source of truth, the NOC is a controlled historical snapshot, and the PDF is the final presentation layer.**

That gives you three clean layers:

```text
EMPLOYEE MASTER DATA
        ↓
NOC WORKING DATA / SNAPSHOT
        ↓
FINAL A4 DOCUMENT
```

This prevents a major operational problem where changing an employee's passport, trade, company, or nationality months later accidentally changes an old NOC.
